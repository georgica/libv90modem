# V.92 quick connect for the answering side: scope (2026-11-26)

Primary sources: V.92 (11/2000) in `v90d/refs/itu`, V.8bis (11/2000) in
`modem-research/itu`. Our code: libv90modem main, 0.7.3 (81da731). BinModem
was read for how it behaves, and none of its code was copied.

## 1. What V.92 asks of the digital (answering) modem

**Short Phase 1, opened with ANSam (9.2.4.1, Figure 3).** This is the case
that matters. The caller hears ANSam for 1 s, then sends **QC1a** followed
immediately by CM (9.2.1.1). QC1a is on V.21(L) and uses V.8-style
10-bit frames (Table 2): ten ones, the sync character 0x55, and one
character holding: analogue (0), QC (0), **P** (LAPM wanted) and
**UQTS** (WXYZ: one of 15 Ucodes, or 1111 = "clear down from on-hold").
Then the same sync and character again. We must:
- recognise QC1a during ANSam, before acting on the CM behind it;
- send **QCA1d** (V.21(H), Table 13). It carries digital (1), QCA (1), our
  P bit and **LM**, the ANSpcm level we choose (-9.5/-12/-15/-18 dBm0);
- send 75 ± 5 ms of silence, then **QTS** (128 × {+V,+0,+V,−V,−0,−V},
  768T, V = the caller's UQTS), then **QTS\** (48T), then **ANSpcm**.
  ANSpcm is a 301-symbol codeword cycle, about 2100 Hz, with a phase
  reversal every 3612 symbols, and must equal Tables 7–10 exactly
  (8.3.1, 8.3.6);
- **hold data-frame alignment from QTS's first symbol**, which is frame
  interval 0 (8.3.6). This replaces V.90's "first symbol of Sd". Our Sd
  must therefore start on QTS's 6-symbol grid. That alignment is what lets
  the caller reuse the robbed-bit and pad positions it stored;
- on **TONEq** (980 Hz), send 75 ± 5 ms of silence, then Phase 2. If there
  is no TONEq within 2 s of QCA1d, send ANSam and run plain V.8 (9.2.4.3);
- if both P bits are 1, skip V.42's ODP/ADP (9.2.5). Today
  `answer_odp_bypass` takes LAPM from CM/JM; under QC there is no CM, so
  the P bits must stand in for it.

**Short Phase 1, opened with CRe (9.2.4.2, Figure 5).** A digital modem
that sends CRe "shall condition its receiver to detect QC2a, QC2d and
V.8bis signals". QC2a is a V.8bis-framed message on V.21(H) with message
type 1101 (V.8bis Table 3: "Defined in ITU-T V.92"). Its 16-bit
identification field holds UQTS, P, QC/QCA and analogue/digital
(Table 3/V.92). The caller sends it after "the initial 50 ms of CRe"
(9.2.1.2), so it overlaps our 390 ms CRe. On QC2a we stop CRe, send
**QCA2d** (V.21(L), Table 14), then the same silence, QTS and ANSpcm. If
TONEq does not come within 2 s, send ANSam and go to 9.2.4.1. With no
V.8bis signal and no QC2x within 3 s of CRe, send ANSam (we already do
this after 1 s).

**Short Phase 2 (9.4.1, Figure 9).** This is independent of short
Phase 1. It runs when our INFO0d has bit 26 set and the caller's INFO0a
has bit 27 set, and the caller asks only when it means PCM upstream or
V.90 (9.4). The sequence: INFO0d, then Tone B ≥ 50 ms. When Tone A is
heard, **we** reverse Tone B, send it 10 ms more, then go silent. The
caller's reversal comes 40 ± 1 ms after it hears ours, so RTDEd is the
interval minus 40 ms. Then we receive INFO1a: Table 18 (PCM upstream),
or **Table 19** (V.34 upstream; the caller names the symbol rate 3000 to
3429 and the carrier). Skipped: L1/L2 probing in both directions and
INFO1d. Recovery: no Tone A reversal, or no INFO1a, within 2500 ms →
full Phase 2 (9.4.1.2.2–3).

**Phase 3 under QC.** Nothing new. The caller can ask for a zero-length
DIL (Figure 11, 9.5.1.1.11 and 9.5.1.1.13: SCR instead of DIL, and Ri
once trained). MD may be 0.

**What is stored, and by whom.** Only the analogue modem keeps
anything. V.92 1 j) speaks of "reduced start-up time on recognized
connections". Everything the server needs arrives in the call itself:
UQTS and P in QC1a, the RTD from short Phase 2, and the rest in INFO1a.
**The server needs no memory per caller.** BinModem keys its memo by the
number dialled (UQTS, law, RTD, upstream choice) and sends QC1a only to a
place where it has reached V.92 data mode before. It can also be forced
with `BINMODEM_V92_QC=always`.

## 2. QC and our V.8bis opening (K56flex kept on)

- **Why QC never happens on our server.** BinModem sends QC1a + CM on our
  ANSam. `v8rx` accepts only the CM sync (`V8_SYNC_CM_JM`), so QC1a is
  dropped. We answer the CM with JM, and the caller "shall proceed
  according to V.8" (9.2.1.1). V.8bis has nothing to do with it:
  BinModem does not implement QC2a, and without `+A8E` it ignores our CRe.
- **V.92 explicitly allows QC after V.8bis**: 9.2.4.1 applies "even when a
  previous V.8 bis session has timed out". So K56flex stays as it is, and
  we do not hold V.8bis back. A QC1a caller simply gets its ANSam 1.79 s
  later (3.4 to 3.8 s later if it ran V.8bis), and QC then saves the rest.
- **QC2a can be heard during CRe, using the V.21(H) receiver** we already
  run for MS. The risk is our own CRe echo: 2002 Hz sits near the 1850 Hz
  space tone. Answering QC2a skips V.8bis/CL/MS entirely, so it never
  touches K56flex: a QC caller is V.92, not K56flex.
- **Options that keep K56flex:** (i) QC1a in ANSam only; (ii) also
  QC2a/QCA2d in CRe; (iii) open with ANSam for some callers. Option (iii)
  is not possible, because a QC caller is silent until it hears ANSam.

**The owner's CL question.** Our CL decodes as follows:

| Part | Content |
|---|---|
| Octet 0 (0x12) | CL, **revision 1** |
| I-field NPar(1) (0xc9) | V.8 follows, transmit ACK(1), NS present |
| I-field SPar(1) (0x80) | no network type |
| S-field | Data → V.42 only (0xc2) |
| NS | the K56flex block |

- *Conformant?* Yes. V.8bis puts no minimum on a CL. Receivers "shall
  parse all information blocks and ignore information that is not
  understood" (8.2.3). Revision 1 has no V.90/V.92 code points at all,
  since revision 2 added PCM (Summary; Table 6-3c/d). One wrinkle: a clear
  network-type bit "indicates that the DCE is connected to an analogue
  PSTN" (Note, Table 5-2), which is not true of us. Nothing in V.8bis or
  V.92 acts on it.
- *Name modulations?* No. V.8 follows (the V.8 bit is set), and "the V.8
  CM and JM message fields shall take priority over those set in the V.8
  bis MS" (V.8bis 9.9.1). Listing V.92/V.90 digital would also mean
  revision 2, the network-type and digital-PSTN bits (Table 6-3c/d Note),
  and changing a CL that K56flex clients are proven against.
- *Could it hide V.92?* Not by the standards. V.92 capability is only
  signalled in INFO0 (9.3, and 9.1's NOTE: V.8 has no way to say V.92).
  QC2a is triggered by the CRe signal, and QC1a by ANSam (9.2.1.1–2). No
  V.92 clause refers to CL content. BinModem even has a unit test with our
  live CL: it selects Data + V.42 with V.8 and leaves the modulation to V.8.
- **Worth changing: not the CL, but our silence to that MS.** A valid MS
  without the K56flex block gets nothing from us today. V.8bis 9.7 says a
  positively acknowledged MS gets ACK(1) "followed immediately by …
  ANSam", and 9.5 says one we cannot serve gets NAK(2)/(3). Sending ACK(1)
  for Data/V.42 + V.8 would be conformant and slightly faster. BinModem
  with `+A8E` sends exactly that MS.

## 3. What exists and what to build

**Reused:**
- V.8 answerer (`modem/v8ans`, `v8rx`: ANSam with the V.21(L) receiver
  running, a V.21(H) transmitter);
- V.8bis framing and receiver (`v8bismsg`);
- V.92 Phase 2 for the digital modem (`p2d`: INFO0d bit 27, ranging,
  INFO1a Table 18; `info.c` already encodes and decodes short_p2 bits
  26/27);
- V.92 Phases 3 and 4, including the zero-length DIL path (`v92_p34d`
  9.5.1.1.13, tested in `test_v92call` "no DIL");
- the G.711 octet interface (exact codewords);
- `tonedet`; the ODP bypass; the V.92 simulated caller (`sim/v92call`,
  `p2a`, `v92a`, `v92chan`).

**New work, answering side:**

| Piece | Approx. lines |
|---|---|
| QC1a receive (sync 0x55, two equal copies) and QCA1d in `v8ans` | ~120 |
| QTS/QTS\/ANSpcm generator (both laws, 4 levels, checked against Tables 7–10) and the frame-0 counter carried into Sd | ~200 |
| TONEq wait, 2 s fallback, `answer.c` phase, P → LAPM/ODP, log line and status field | ~150 |
| Short Phase 2 in `p2d` (we reverse first, RTD, Table 19 INFO1a, recovery to full Phase 2) and Table 19 wiring into `start_p34` | ~300 |
| *Optional:* QC2a/QCA2d in `v8bis` | ~150 |

**Simulated caller:** QC1a + CM, QCA1d receive, an ANSpcm detector,
TONEq, short Phase 2 (both INFO1a forms), a stored "memo" to replay:
about 500 lines.

**Size.** The answering side plus the simulated caller comes to about
1,300–1,500 lines with tests. That is roughly 60 % of x2 (about 2,200
source lines) and 40 % of K56flex (about 3,450). The risk is much lower:
everything is in the ITU text, with no reverse engineering. A real calling
side (orig.c: QC1a, an ANSpcm/QTS receiver, short Phase 2 analogue, a memo
API) would add roughly x2's size again.

## 4. Approaches

| | Scope | For | Against |
|---|---|---|---|
| **A** | Answering only: 9.2.4.1 (QC1a in ANSam) + short Phase 2; sim caller | Fixes BinModem and any V.92 caller on the path every ISP that opens with ANSam uses; V.8bis and K56flex untouched; no per-caller state | A V.8bis-QC caller waits for ANSam (about 2 s lost) |
| **B** | A + QC2a/QCA2d during CRe (9.2.4.2) | Full answering conformance for a CRe opener; saves 2–3.4 s for V.8bis-QC callers | No known client sends QC2a (BinModem does not); echo of our CRe vs V.21(H) |
| **C** | QC Phase 1 only, always full Phase 2 (INFO0d bit 26 clear) | Smallest (~500 lines) | Gives up about half the gain; short Phase 2 is the cheaper half to build |

Recommendation: **A now. B as a follow-up** once a QC2a caller is known,
or behind a flag. The calling side gets the simulated caller only; a real
calling QC with a memo API is a later, separate item. **Modem-on-hold is
out of scope.** A QC1a whose UQTS is 1111 (clear down from on-hold) is
treated as "no QC": we ignore it and the CM behind it decides.

## 5. Testing

1. **Units.** Check QC1a/QCA1d bits against Tables 2, 11 and 13 (every
   UQTS, both P values, a corrupt second copy). Check ANSpcm octets
   against Tables 7–10 for both laws, and QTS/QTS\ octet streams.
   Re-derive the tables with a tool from the formula and the G.711
   quantiser rather than OCR them.
2. **Simulated calls** (`sim/v92call` as QC caller):
   - QC + full Phase 2; QC + short Phase 2 (PCM upstream);
   - QC + short Phase 2 + Table 19 (V.90); QC + DIL N = 0;
   - no TONEq → ANSam/V.8; short Phase 2 recoveries;
   - V.92 off (QC1a ignored, CM honoured); UQTS = 1111; A-law;
   - robbed bits and pads with Sd checked on QTS's frame grid;
   - K56flex on: CRe, then ANSam, then QC.

   Regression: x2/K56flex/HST and plain V.8 timings unchanged. Run on the
   usual ports.
3. **Live, local test server.**
   - BinModem with `BINMODEM_V92_QC=always`, then the default
     (first call full, second QC), each with `+A8E` off and on.
   - Read it from our log line and status fields (QC heard, UQTS, P, LM,
     TONEq delay, short Phase 2, DIL N). The only recordings are of
     Phases 1–2, which come before error control, so they fit the privacy
     rule.
   - BinModem is a developer's modem: we follow the spec, with no
     workarounds for it.
   - Later: the Conexant CX93001 and U.S. Robotics 5686 that have already
     called the unit, with QC enabled (`AT+PQC`).

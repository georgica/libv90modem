# V.92 Quick Connect on the answering side (0.7.4): design

**Status:** owner choices made on 2026-11-26. Background, clause references and size estimate: `2026-11-26-v92-qc-scope.md`.

## Why
V.92 callers that support Quick Connect (QC), BinModem among them, never get it from Netstalgia; big ISPs give it to them. The cause is our V.8 receiver. A QC caller answers our ANSam with QC1a and then CM (V.92 9.2.1.1). We drop the QC1a, answer the CM with JM, and the call falls back to a full start-up.

The goal is that a V.92 caller asking for QC gets QC from us. Everything else must behave exactly as in 0.7.3.

## What we build (approach A from the scope)
1. **Answering QC after ANSam (V.92 9.2.4.1, 9.2.4.3).**
   - While sending ANSam, recognise QC1a.
   - Reply with QCA1d, then QTS, QTS\ and ANSpcm, and wait for TONEq.
   - If anything is missing or late, fall back to ANSam/V.8 within V.92's 2 s, exactly as today.
   - With QC there is no CM, so the P bits in QC1a/QCA1d decide LAPM and the ODP/ADP bypass (9.2.5).
   - Data-frame alignment starts at QTS's first symbol (8.3.6).
2. **Short Phase 2 (9.4.1)**, including the Table 19 INFO1a. It reuses the V.92 Phase 2/3/4 code and the zero-length DIL path that already exist.
3. **No separate setting.** QC is part of `V90M_MOD_V92`: any port that offers V.92 answers QC, and a caller that doesn't ask for it sees no change.
4. **A V.8bis fix.** A valid MS without the K56flex block (for example "Data + V.42, the rest via V.8", which BinModem sends with `+A8E` on) that requests acknowledgement (V.8bis 9.9) gets ACK(1) and then ANSam (V.8bis 9.7, 9.9.1), instead of today's silence.
5. **Reporting.** The per-call status shows whether QC was attempted, accepted or fell back, through an additive API in the 0.7.x style (a new function and struct; no struct grows).

## What stays as it is
- V.8bis, our CL and K56flex. The owner keeps K56flex on, and V.92 9.2.4.1 allows QC after a V.8bis exchange.
- QC2a during our CRe (9.2.4.2). No known client sends it, and our own echo makes detection risky.
- The calling side: only a simulated QC caller, for tests.
- Modem-on-hold.

## ANSpcm level
Our Phase 2 nominal transmit power, not a fixed -12 dBm0 (my call, so the level is consistent with the rest of our start-up).

## Tests
- **Simulation:** our V.92 caller in `sim/`, extended with QC1a, TONEq and the short Phase 2, written from the V.92 text, not from library code. Cases:
  - QC accepted, reaching data;
  - QC1a with no TONEq, falling back to a full start-up;
  - a caller without QC, unchanged;
  - QC after a V.8bis exchange;
  - LAPM bypass on and off.
- **Proofs:** every existing golden, replay (742) and bench hash byte-identical for callers that don't send QC1a.
- **Live:** we run BinModem ourselves against the local test server: QC forced (`BINMODEM_V92_QC=always`) and the default, each with `+A8E` off and on.

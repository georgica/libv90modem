# HST and MNP on the answering side: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** libv90modem 0.7.0 answers U.S. Robotics HST callers (forward
channel 4800 to 14400, back channel 450 or 300, MNP with the HST profile,
reversals and rate changes) and gives MNP-only callers error control
through a general MNP endpoint, both off by default.

**Architecture:**
- MNP (V.42 Annex A, framing modes 2 and 3) is a new mode of the existing
  endpoint `v42ec_t` (`v42/mnp_frame.[ch]`, `v42/mnp.[ch]`), sharing a union
  with LAPM; the answering endpoint takes an LR beside the ODP.
- HST's extras (0xC0, streamlined layouts, attention codes) are a profile
  of that endpoint, active only when the endpoint is linked to a modem
  (`v90m_ec_link_hst()`) and the modem is in `ANS_HST`; the two talk through
  a mailbox, `hst_link_t`, that lives in the HST engine.
- The pump is a new answering branch after ANSam (`ANS_HST_WAIT`, then
  `ANS_HST`, `modem/ans_hst.c`) with an 8-DPSK back channel
  (`modem/hst_back.c`) and a band-split forward channel on `v32tx`
  (sharper pulse) and `qamrx` (`modem/hst_fwd.c`); its engine `hst_t` lives
  in `answer_t.u`.

**Tech Stack:** C99 fixed point, GNU make, POSIX sh, Python 3 (table
generator, the capture converter), qemu-user, Bootlin cross toolchains;
BinModem (Rust, outside the repository) as a black-box peer.

**Spec:** `docs/superpowers/specs/2026-11-24-hst-mnp-design.md` (cited as
"spec", decisions D1–D25 are its "Decided how" table). Research:
`docs/hst/binmodem-facts.md` (BF §n), `docs/hst/public-sources.md` (PS §n),
`docs/hst/library-map.md` (LM §n). Executors read the spec section a task
names before starting it. Models: the x2 and K56flex plans, the audit plan.

## Review Focus

1. **Block size.** A host may call `v90m_process_*` with any n. An HST call with the endpoint linked, run with n = 1, 160 and 4000, gives identical transmit samples, the same event sequence and the same endpoint status at the end (the mailbox is touched only from getbit/putbit/tick). Test in Task 18.
2. **A linked endpoint on a call that is not HST, with a host that does not reset it at `CONNECTED`.** A V.32bis caller with an ODP gets LAPM; one with no error control gets start-stop after T400 counted from the modem's decision, not from the first sample (the linked endpoint holds T400 while the decision is pending). Test in Task 9.
3. **A start-stop caller whose typed text contains `16 10 02`** (SYN DLE STX) with MNP on: no false LR (only a CRC-valid LR counts); the call goes to start-stop after T400 and every typed character, those three included, is delivered. Test in Task 5.
4. **Sequence wrap under loss.** More than 256 LTs and more than 256 LNs on one link, with 1 % of frames lost, across V(S) 255 → 0: the data arrive intact and in order, each LN delivered once. Test in Task 4.
5. **An HST call on an A-law line.** The answerer's linear front end makes HST independent of the law: an A-law HST call reaches data at 14400/450 like a mu-law one. Test in Task 18.
